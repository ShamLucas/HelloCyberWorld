# Note : Diagnostic SSD Samsung 870 EVO via DeskPi Pro V2

Date : 2026-03-19

## Matériel

- SSD : Samsung SSD 870 EVO 1TB (S/N: S626NF0R212175B, firmware SVT01B6Q)
- Bridge : DeskPi Pro V2 ASMedia ASM1153E (USB ID: 174c:55aa)
- Pi : Raspberry Pi 4 8Go, Ubuntu 25.04 (kernel 6.14.0-1019-raspi)

## Problème

Le SSD est détecté au boot mais toute tentative d'écriture échoue avec des erreurs I/O :
- `Medium Error: Peripheral device write fault`
- `Hardware Error: Internal target failure`
- SMART illisible (`scsi error aborted command`)

## Ce qui a été tenté

1. **Quirk UAS** : ajouté `usb-storage.quirks=174c:55aa:u` dans `/boot/firmware/cmdline.txt`.
   Résultat : le driver passe de `uas` à `usb-storage`, le SSD reste connecté (ne se déconnecte plus)
   mais les erreurs d'écriture persistent.

2. **Débranchement du disque WD externe** pour éliminer un problème de courant USB.
   Résultat : mêmes erreurs d'écriture, ce n'est pas un problème d'alimentation.

3. **SMART** via smartmontools : le SSD est identifié mais toutes les commandes SMART échouent
   (le bridge ASMedia ne transmet pas les commandes ATA correctement).

## Conclusion

Impossible de déterminer avec certitude si le problème vient du SSD ou du bridge DeskPi,
car le bridge bloque aussi les diagnostics SMART.

## Prochaines étapes

- [ ] Tester le SSD sur un autre PC (en SATA direct ou via un autre adaptateur USB-SATA)
      -> Si ça marche : le bridge DeskPi est défectueux
      -> Si ça ne marche pas : le SSD est défectueux (garantie Samsung 5 ans)
- [ ] Si le bridge est en cause, vérifier firmware DeskPi ou envisager un autre boîtier
- [ ] Le quirk UAS (`usb-storage.quirks=174c:55aa:u`) reste dans cmdline.txt, il est inoffensif

## État actuel du Pi

Le Pi fonctionne normalement sur la carte SD (mmcblk0, 59 Go).
Tous les services (Nginx, julie.hellocyberworld.com) tournent.
Le SSD est détecté mais inutilisable en écriture.
