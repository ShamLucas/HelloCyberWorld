# Note : Déploiement de julie.hellocyberworld.com

## Contexte

Besoin urgent de publier une page markdown accessible sur internet pour un anniversaire (2026-02-28).
La page est une lettre personnelle convertie en HTML statique, servie par Nginx avec HTTPS.

## Déploiement initial (manuel, 2026-02-28)

Le premier déploiement a été fait manuellement en SSH sur le Pi, hors Ansible :
- Installation de pandoc, certbot, python3-certbot-nginx
- Conversion `julie.md` -> HTML via pandoc avec CSS embarqué
- Virtual host Nginx créé + symlink sites-enabled
- Certificat Let's Encrypt obtenu via `certbot --nginx`
- DNS : entrée `julie` (type A) configurée chez OVH vers l'IP Freebox

Certificat : `/etc/letsencrypt/live/julie.hellocyberworld.com/fullchain.pem`
Renouvellement automatique via timer systemd certbot.

## Intégration Ansible (2026-03-19)

Le déploiement manuel a été intégré dans la structure Ansible via 3 nouveaux rôles :

- **`markdown-site`** : rôle générique pour déployer des pages markdown en HTML statique.
  Les sources sont dans `ansible/sites/<nom>/` et la config dans `group_vars/raspberrypi.yml`.
- **`certbot`** : rôle dédié aux certificats Let's Encrypt (extrait de l'ancien `pi-setup`).
- **`pi-hardware`** : rôle dédié à la config matérielle du Pi (EEPROM, SSD).

### Pour mettre à jour la page via Ansible

1. Modifier `ansible/sites/julie/julie.md` (et/ou `julie.css`)
2. Lancer :
```bash
cd ansible
ansible-playbook playbook.yml --limit raspberrypi
```

### Pour ajouter une nouvelle page

1. Créer `ansible/sites/<nom>/<nom>.md` + `<nom>.css`
2. Ajouter dans `ansible/group_vars/raspberrypi.yml` :
```yaml
markdown_sites:
  - name: <nom>
    domain: <nom>.hellocyberworld.com
    title: "Titre"
    markdown_file: <nom>.md
    css_file: <nom>.css
```
3. Ajouter le domaine dans `certbot_domains`
4. Configurer le DNS chez OVH
5. Lancer le playbook
