# 📒 Raspberry Pi Lab avec Freebox Révolution

Dans mon cas, mon raspberry pi est installé derrière ma Freebox qui a l'avantage d'offrire quelques fonctionnalités pouvant être utiles à mon projet. Ce document expliquera comment je l'ai configuré.

## 🔹 Services Freebox Révolution pertinents

| Service           | Utilité dans ton projet Raspberry Pi Lab                     |
|-------------------|--------------------------------------------------------------|
| DHCP              | Attribution d’IP locales (on le garde simple au début).         |
| NAT / Redirection | Rediriger 80/443 vers le Pi pour exposer tes services.       |
| DNS Dynamique     | Associer ton domaine à l’IP publique, utile si IP dynamique. |
| VPN (OpenVPN)     | Accès sécurisé à ton réseau depuis l’extérieur.              |
| Pare-feu Freebox  | Première couche de sécurité (bloquer tout sauf 80/443).      |
| UPnP              | **À désactiver** (trop risqué).                              |
| NAS (FTP/SMB)     | Redondant → préfère ton Pi.                                  |
| Contrôle parental | Pas utile pour le lab.                                       |

## 🔹 Configuration du VPN & des redirections

L'interface est plutôt bien faite. 

### Rerirection des ports

![Admin Freebox](/doc/img/InterfaceAdminFreebox.png "Interface Administration Freebox")

- La redirection se fait dans `Paramètres de la Freebox > Mode Avancé > Gestion des ports`

![Redirections Freebox](/doc/img/GestionDesPortsFreenox.png "Redirections Freebox")

- On redirige les ports 80 & 443 > Ajouter une redirection

![Ports 80 & 443](/doc/img/RedirectionFreeboxPorts80et443.png "Redirection Ports")

### Configuration du server OpenVPN

La aussi, c'est plutôt bien fait. Tout est dans `Paramètres de la Freebox > Mode Avancé > Server VPN`

- On choisi Open VPN Routé et on ajoute un utilisateur en saisissant compte et mot de passe.
- On peut ensuite télécharger une fichier de configuration

![Open VPN Routé](/doc/img/OpenVPNFreebox.png "Open VPN")

Perso, sur mon mac (Mac OS Ventura), j'ai du faire des modifs dans le fichier de config téléchargé. Dans mon cas, le fichier s'appelle `config_openvpn_routed_Lucas.ovpn`.

Il est structuré de la façon suivante :

```
client
remote 82.65.193.113 58447
proto udp
nobind
dev-type tun
pull
dev tun0
# redirect-gateway   # <-- commenté, donc pas de full tunnel
route 192.168.0.0 255.255.255.0
auth-user-pass
auth-retry interact
mssfix 1452
explicit-exit-notify 3
cipher AES-256-CBC
remote-cert-tls server
verify-x509-name "C=FR, O=Freebox SA, CN=Freebox OpenVPN server d82bbef9dd39dee5b4127fb4da154cd7"
<ca>
[...]
</ca>
<cert>
[...]
</cert>
<extra-certs>
[...]
</extra-certs>
<key>
[...]
</key>
```

- J'au du supprimer la ligne tun-ipv6  car j'avais le message 

> 'tun-ipv6' a été déprécié dans OpenVPN 2.4 et supprimé dans OpenVPN 2.4

- Plutot que rediriger tout le trafic ( y compris Google, Youtube, etc ), comme mon but n'est que d'accéder à ma freebox et mon raspberry pi, j'ai remplacé par `route 192.168.0.0 255.255.255.0`

- Petite attention, si vous êtes à distance, dans un autre réseau qui contient des adresses 192.168.1.*, elles seront en compétition avec les adresses que vous tentez de joindre avec le VPN.

### Nom de domaine

Dans `Paramètres de la Freebox > Mode Avancé > Nom de domaine`, on indique le nom de domaine, et sur OVH, on saisi l'ip exterieur de la box.

## 🔹 Notes complémentaires
- ⚠️ **Ne jamais exposer SSH directement** → utiliser VPN ou réseau local.  
- 🔑 Gestion des certificats SSL : automatisée via **Let’s Encrypt** (Nginx/Traefik).  
- 📦 Déploiement : via **Ansible + Docker Compose** pour chaque service.  
- 📜 Logs : commencer simple (`journalctl`, `logrotate`), évoluer vers Loki/Grafana si besoin.  
- 🔄 Tests : toujours valider la config sur la VM Vagrant avant de pousser sur le Pi.
