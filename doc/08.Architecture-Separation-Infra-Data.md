# Architecture : Séparation HelloCyberWorld (Infra) vs Sites (Data)

**Date** : 21 mai 2026  
**Objectif** : Clarifier la philosophie du projet et structurer pour réutilisabilité, pédagogie, et automatisation IA.

---

## 🎯 Vision

**HelloCyberWorld** = Infrastructure générique pour publier du contenu markdown en tant que pages web avec HTTPS.

Le projet doit être :
- ✅ **Réutilisable** : Quelqu'un clone, adapte 2-3 fichiers config, c'est prêt.
- ✅ **Pédagogique** : La doc montre chaque étape, explorable, pas une "boîte noire DevOps".
- ✅ **Automatisable** : Une IA peut suivre la même doc pour déléguer l'aspect technique.
- ✅ **Modulaire** : Infra (code) et contenu (data) séparés pour éviter mélange de logique.

**Non-objectifs** :
- ❌ Héberger du contenu perso multi-user par défaut (single-tenant mindset).
- ❌ Être un CMS full-featured (volontairement minimaliste).
- ❌ Forcer les utilisateurs à garder le contenu dans ce repo.

## 👥 Flux d'Utilisation

### **Cas 1 : Humain Curieux / Pédagogique**

**Objectif** : Apprendre à déployer un site markdown.

**Étapes** :
1. Clone HelloCyberWorld
2. Lit [doc/03.Add-Markdown-Pages.md](03.Add-Markdown-Pages.md) (détail ci-dessous)
3. Crée dossier `ansible/sites/mon-truc/`
4. Ajoute `mon-truc.md` + `mon-truc.css`
5. Édite `ansible/group_vars/[dev|hp_envy].yml` pour ajouter domaine/config
6. Lance playbook
7. Teste localement (Vagrant) ou prod (HP/Pi)

**Valeur** : Comprend chaque couche (Nginx, Certbot, Ansible, DNS).

---

### **Cas 2 : IA Automatisant**

**Objectif** : "Publie cette réflexion en markdown sur mon site."

**Prompt IA** (exemple) :
> Référence le projet HelloCyberWorld. Suis la procédure dans `doc/03.Add-Markdown-Pages.md`. Crée un nouveau fichier `ansible/sites/reflexion-du-jour/reflexion-du-jour.md` avec ce contenu [texte]. Mets à jour les variables Ansible pour ajouter ce domaine. Lance le playbook sur hp_envy.

**IA exécute** :
1. Lit la doc standardisée (reproduit Cas 1)
2. Génère fichiers `.md` + `.css`
3. Modifie `group_vars/hp_envy.yml`
4. Exécute: `ansible-playbook playbook.yml --limit hp_envy -K`
5. Valide: curl https://reflexion-du-jour.hellocyberworld.com

**Valeur** : Publication rapide, délégation technique, pas de "magic".

---

### **Cas 3 : Réutilisation par Tiers**

**Objectif** : Quelqu'un d'autre utilise la stack pour son propre blog.

**Étapes** :
1. Clone HelloCyberWorld
2. Crée son propre repo privé ou public pour contenu
3. Adapte `inventory.ini` (ses IPs, domaines)
4. Adapte `group_vars/all.yml` + `group_vars/production.yml` (ses données)
5. Cree/remplit `ansible/sites/` ou pointe un submodule
6. Même doc s'applique, juste ses données

**Valeur** : Stack infra réutilisable, évite copy-paste code, apprentissage transférable.

## 📖 Doc Clef : "Add Markdown Pages"

Ce fichier (`doc/03.Add-Markdown-Pages.md`) doit être **suffisamment complet pour IA et humain**.

**Structure recommandée** :

```markdown
# Comment Ajouter une Page Markdown

## Rapide (3 min)

1. Crée dossier : `mkdir -p ansible/sites/ma-page`
2. Crée fichiers :
   - `ansible/sites/ma-page/ma-page.md`
   - `ansible/sites/ma-page/ma-page.css`
3. Édite `ansible/group_vars/hp_envy.yml`, ajoute:
   ```yaml
   markdown_sites:
     - name: ma-page
       domain: ma-page.hellocyberworld.com
       title: "Mon Titre"
       markdown_file: ma-page.md
       css_file: ma-page.css
   
   certbot_domains:
     - ma-page.hellocyberworld.com
   ```
4. Lance : `cd ansible && ansible-playbook playbook.yml --limit hp_envy -K`
5. Ajoute DNS chez OVH (si public) ou `/etc/hosts` local (si test)
6. Visite : https://ma-page.hellocyberworld.com

## Détail (20 min - comprendre chaque étape)

### Étape 1 : Créer les fichiers source

...explications Markdown, CSS, variables Jinja2...

### Étape 2 : Configurer Ansible

...explications inventory, group_vars, rôle markdown-site...

### Étape 3 : Déployer

...explications playbook, handlers, Nginx reload...

### Étape 4 : SSL + DNS

...explications Certbot, DNS OVH, redirection NAT box...

## Checklists de Validation

**Avant déploiement** :
- [ ] Fichiers `.md` et `.css` existent
- [ ] Noms coherents (exemple: `ma-page.md` + name: `ma-page`)
- [ ] Variables Ansible formatées correctement (YAML space, not tab)
- [ ] Syntaxe playbook : `ansible-playbook --syntax-check`

**Après déploiement** :
- [ ] HTTP repond: `curl -I http://localhost` (local Vagrant)
- [ ] HTTPS repond: `curl -I https://mondomaine.com` (public)
- [ ] Certbot valide: `ssh lucas@192.168.1.139 "sudo certbot certificates"`
- [ ] Nginx écoute 443 : `ss -ltnp | grep :443`

## Troubleshoot

- Port 443 pas ouvert ? Vérifier NAT box Freebox
- Certbot fail ? Domaine DNS doit pointer ip publique
- Nginx reload fail ? Vérifier syntax: `sudo nginx -t`
```

**Clef** : Même doc **Rapide 3min** + **Détail 20min** = IA + humain satisfaits.

## 🔗 Intégration Submodule (Optionnel)

**Pour lier HelloCyberWorld-Sites facilement** :

```bash
# Depuis HelloCyberWorld
git submodule add https://github.com/ShamLucas/HelloCyberWorld-Sites.git ansible/sites/hello-sites

# Utilisateur qui clone
git clone https://github.com/ShamLucas/HelloCyberWorld.git
cd HelloCyberWorld
git submodule update --init --recursive
# → ansible/sites/hello-sites/ contient contenu

# Créer symlink vers julie (exemple)
ln -s hello-sites/julie ansible/sites/julie
```

**Avantage** : Référence commune, versioning facile.  
**Inconvénient** : Courbe apprentissage submodule, complexité.

## 🎓 Bénéfices Pédagogiques

**Pour apprenant Ansible** :
- Rôle générique `markdown-site` → comprendre templating, loops
- Gestion multi-env → inventory + group_vars
- Déploiement réel → certificats, DNS, NAT

**Pour apprenant Linux/Infra** :
- Nginx vhosts, SSL, rewriting
- Systemd, timers (Certbot auto-renew)
- Diagnostique réseau (DNS, ports, logs)

**Pour apprenant DevOps** :
- Idempotence (rejouer playbook = no-op)
- Pattern Infrastructure-as-Code
- Séparation infra/data/config

**Pour apprenant automatisation IA** :
- Doc structurée = prompt clair
- Même workflow humain = reproductible IA
- Décision récursive (choix config → impact playbook)
