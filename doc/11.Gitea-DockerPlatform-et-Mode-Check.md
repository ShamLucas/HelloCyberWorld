# 11. Gitea dans docker-platform, et ce que le mode check a révélé

> Séances des 22 et 25/09/2026. **Gitea n'est pas encore déployé** : le
> `--check --diff` lancé avant l'application a révélé un conflit entre Ansible
> et Certbot sur la production, qui interdit de rejouer le play HP Envy en
> entier. Cette fiche documente le code écrit, le diagnostic et les pièges.

## 1) Objectif et choix V1

Ajouter Gitea (forge git) au rôle `docker-platform`, sur le modèle de
Portainer, puis le déclarer dans la sauvegarde.

- **Gitea dans `docker-platform`**, pas dans un rôle dédié : au plus vite.
  `doc/10` §4 demande à terme que chaque service porte sa propre sauvegarde ;
  la factorisation viendra quand deux services tourneront côte à côte.
- **Base SQLite** dans le volume, pas de Postgres en V1.
- **SSH de Gitea désactivé** : le port 22 de l'hôte appartient au sshd du
  serveur. Clone et push en HTTP.
- **Écoute sur `127.0.0.1:3000`**, accès par tunnel SSH. Pas de vhost, pas de
  DNS, pas de certificat : une forge fraîche, avec son assistant
  d'installation ouvert, ne s'expose pas à Internet.

## 2) Le code

`roles/docker-platform/defaults/main.yml` :

```yaml
# Gitea
gitea_enabled: true
gitea_bind_address: 127.0.0.1
gitea_host_port: 3000
gitea_image: gitea/gitea:1.27.3
gitea_volume_name: hcw_gitea_data
```

et le volume ajouté à la liste lue par le script de backup :

```yaml
docker_backup_volumes:
  - "{{ portainer_volume_name }}"
  - "{{ gitea_volume_name }}"
```

`roles/docker-platform/templates/gitea-compose.yml.j2` :

```yaml
services:
  gitea:
    image: {{ gitea_image }}
    container_name: gitea
    restart: unless-stopped
    environment:
      - USER_UID=1000
      - USER_GID=1000
      - GITEA__database__DB_TYPE=sqlite3
      - GITEA__server__DISABLE_SSH=true
      - GITEA__server__ROOT_URL=http://localhost:3000/
    ports:
      - "{{ gitea_bind_address }}:{{ gitea_host_port }}:3000"
    volumes:
      - gitea_data:/data
    networks:
      - internal

volumes:
  gitea_data:
    name: {{ gitea_volume_name }}

networks:
  internal:
    external: true
    name: {{ docker_network_name }}
```

`roles/docker-platform/tasks/main.yml` : le répertoire
`{{ docker_services_dir }}/gitea` ajouté à la boucle de création, puis deux
tâches calquées sur Portainer, `Deployer la stack Gitea` (`template`) et
`Lancer la stack Gitea` (`docker compose up -d`), conditionnées par
`gitea_enabled`.

## 3) Lire un compose rendu par Ansible

- **Deux langages dans un fichier.** Les `{{ ... }}` sont du Jinja : Ansible
  les remplace et ne lit rien d'autre. Le reste est du Docker Compose, recopié
  tel quel, interprété par Docker au `up`.
- **Déclarer / utiliser.** Sous le service, `gitea_data:/data` *utilise* le
  volume ; en bas du fichier, `volumes: gitea_data:` le *déclare*. Un chemin
  qui commence par `/` (ex. `/var/run/docker.sock`) est un *bind mount* vers
  un fichier de l'hôte : rien à déclarer.
- **`name:` fixe le vrai nom Docker.** Sans lui, Compose préfixe avec le nom
  du projet (`gitea_gitea_data`). Le script de backup appelle le volume par
  son nom réel : il doit être prévisible.
- **`external: true`** : le réseau `hcw_internal` est créé par Ansible, pas
  par la stack. Sans ça, chaque stack aurait son réseau isolé.
- **`GITEA__section__CLE`** : convention de l'image, chaque variable est
  réécrite dans `app.ini`, section `[section]`, clé `CLE`.
- **Pas de `docker.sock` pour Gitea.** Accéder au socket Docker, c'est être
  root sur l'hôte. Portainer en a besoin, une appli web non.

## 4) Le `--check --diff` sur la production

```bash
cd ansible
ansible-playbook playbook.yml --limit hp_envy --check --diff
```

Attendu : trois `changed` (répertoire Gitea, compose Gitea, script de
backup). Obtenu : `changed=7`, `failed=1`.

| Tâche | Effet si appliqué |
|---|---|
| vhost Nginx Portainer | suppression de `listen 443 ssl`, des certificats, de la redirection HTTPS |
| `nginx` : configuration par défaut | idem pour le domaine principal |
| `nginx` : page d'accueil | page du dépôt jamais déployée depuis août |
| `markdown-site` : fichiers source | **échec** : le contenu des sites est sorti du dépôt |

**Diagnostic.** Les lignes supprimées portent `# managed by Certbot` : le
plugin nginx de Certbot a réécrit les vhosts **sur le serveur** pour y
brancher le HTTPS. Les templates Ansible ne contiennent pas ces lignes. Deux
outils se croient propriétaires du même fichier ; rejouer le play efface le
HTTPS. Les certificats eux-mêmes (`/etc/letsencrypt/`) ne sont pas touchés :
c'est la configuration qui les *utilise* qui disparaît.

**Aggravation par l'échec.** Quand un play échoue, **les handlers ne tournent
pas**. Les vhosts sans HTTPS auraient été écrits sans `Reload nginx` : nginx
aurait continué sur l'ancienne config en mémoire, et le HTTPS serait tombé au
prochain reload ou redémarrage, sans lien apparent avec le déploiement.

**Règle en vigueur** : ne pas jouer le play HP Envy en entier tant que le
conflit n'est pas corrigé.

## 5) Angles morts du mode check

- Les tâches marquées `when: not ansible_check_mode` sont **sautées** : ici
  tout ce qui appelle Docker (`docker compose up`, création du réseau).
- Une image inexistante (`gitea/gitea-ce`, qui n'existe pas : le `-ce` est
  propre à Portainer) passe donc le check sans erreur. Pour Ansible, c'est une
  chaîne de texte dans un template. L'échec n'arrive qu'au vrai `up`.
- Vérifier qu'un tag existe avant de l'écrire :

  ```bash
  curl -s -o /dev/null -w '%{http_code}\n' \
    https://hub.docker.com/v2/repositories/gitea/gitea/tags/1.27.3
  ```

## 6) Pièges rencontrés

- **`-` dans un nom de variable Jinja** : `{{ gitea-bind-address }}` se lit
  `gitea - bind - address`, une soustraction. Underscores uniquement.
- **Faute dans un nom de variable** (`adress`) : erreur `undefined variable`
  au rendu, ou faute recopiée partout qui « marche ».
- **Variable que rien ne lit** : une liste `gitea_backup_volumes` créée à côté
  de `docker_backup_volumes` n'aurait jamais été sauvegardée, sans erreur.
- **YAML : l'indentation décide du parent**, pas l'endroit où l'on écrit. Un
  `environment:` à 4 espaces placé après `networks:` devient une propriété du
  réseau.
- **Copier-coller d'une paire de tâches** : nom, `src`, chemin *et* `when`
  à adapter dans chacune.
- **`--limit`** filtre les machines, pas les plays : les plays sans hôte
  correspondant affichent `no hosts matched`.
- **Le module `ping` d'Ansible n'est pas ICMP** : il teste SSH,
  l'authentification et la présence de Python sur la cible.
- **`ssh hôte 'cmd'`** : pas de TTY, environnement non interactif, et les
  guillemets simples font évaluer la commande par le serveur, les doubles par
  la machine locale.
- **tmux et le trackpad** : sans `set -g mouse on`, le défilement fait
  remonter l'historique du shell. `q` pour quitter le mode copie.

## 7) Suite

1. **Conflit Certbot / nginx.** Un seul propriétaire : les templates Ansible
   portent le bloc HTTPS, Certbot passe en `certonly` et ne touche plus nginx.
   À préparer sur la VM avant la production.
2. **Déployer Gitea sans rejouer le play entier** : un playbook ciblé qui ne
   joue que `docker-platform`, avec `portainer_domain: ""` en `vars:` de play
   (priorité supérieure à `group_vars/`) pour sauter le vhost. Check d'abord,
   trois `changed` exactement, sinon on n'applique pas.
3. **`markdown-site`** : adapter le rôle au contenu hors dépôt.
4. **Sauvegarde** : script de restauration, test vers un volume temporaire,
   version de l'image notée avec l'archive (Gitea migre son schéma au
   démarrage, sans retour possible), et `/etc/letsencrypt/` dans le périmètre.
